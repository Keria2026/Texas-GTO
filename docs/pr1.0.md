# Pr1.0：搜索、画像与真实样本学习闭环

用户将本次交付范围收敛为三项：从当前下注轮起点重新求解、画像实际参与决策、真实样本经过训练和评测后发布。发布名称为 **Pr1.0**，Chrome 数字版本为 **0.8.3**。完整 V1.0 的其余目标见 [roadmap](../ROADMAP.md)，不因本次交付而删除，也不作为 Pr1.0 三项功能的完成声明。

## 1. 从下注轮起点搜索

`capture_pr_v1` 客户端在翻前和翻后都尝试 `MushroomStreetRoot`。先从已验证的公开事件重建当前街道的第一个决策，再在整个公共范围上求解；实际行动节点通过其信息键和街道内深度查询，根行动者可以是另一名玩家。

本轮此前本人真实持牌的策略固定为已发布的搜索策略；没有缓存时固定到有覆盖的 blueprint，不能把已观察行动随意改成概率 1。本人其他可能持牌及基线搜索中的对手策略仍可优化。前一街搜索的加权平均用于历史行动似然；未访问条目必须由已有 blueprint 覆盖，缺失时明确失败。当前策略用于行动，平均策略用于范围，二者独立保存。

历史约束只作用于当前模型窗口的第一手，后续模拟即使再次发到相同私牌也不能沿用上一手约束。历史范围按精确私牌保留搜索平均，仅共享固定快照中同一公开状态和抽象桶的 blueprint 读取；空的历史平均不触发逐手牌重复读取。

缓存按 Origin、source、hand 隔离，只提交仍与当前事件版本一致的有效结果；最多两手、每街一个记录，每记录不超过 4,000 条当前及平均条目且估算载荷不超过 4 MiB。重启或缓存不足时回到有覆盖的 blueprint 约束，不猜造执行历史。目标之后保留两次玩家决策的截断，当前街道历史超过 64 次行动则拒绝本次搜索；自适应街道截断和树外尺寸扩展继续留在 roadmap。

搜索最多 1.5 秒，总推荐最多 2 秒；缺覆盖或预算不足仍只能退回通过原有反馈检查的当前节点基线。未完成的迭代、取消和过期结果不发布。新协议需配套升级 Serve；旧客户端继续使用原来的推荐协议。

## 2. 画像参与八人行动

`public-behavior-v1` 根据决策前公开状态，预测合法行动类别：弃牌、过牌／跟注、下注／加注。特征包括街道、是否面对跟注、底池赔率分桶、筹码／底池比分桶、活跃人数、相对位置和合法类别。总体与具体玩家的粗细条件频率采用先验收缩；玩家只在同一 Origin 和 source 内关联，不跨来源合并昵称。

已发布模型用于历史范围似然、局部搜索的对手响应和后续模拟；本人当前及未来行动不被强制模仿真实样本。个人条件样本少于 8 条时不启用对应个人调整；可用总体模型作为有限支持。对手模型与 blueprint 的混合权重至多 25%，仅总体支持时至多 10%，并按 `n/(n+40)` 缩小。缺失的 blueprint 条目不能用行为模型或均匀分布填补。

搜索形成候选后，以 **75% 当前基线 + 25% 候选**形成待评估建议。使用独立种子、同一世界和配对随机数，模拟两套当前行动分布的完整两手后续净积分。最多取得 32 个有效世界，报告重要性权重有效样本数、平均增益、标准误和 `均值 − 1.96 × 标准误`；有效样本至少 16 且下界大于 0 才启用调整。超时、缺覆盖、数据不足或比较失败均保留基线。

插件区分 `pluribus_blueprint`、`pluribus_search`、`profile_search`，显示画像版本、25% 调整与独立比较。该区间只估计给定模型下的 Monte Carlo 误差，不包含模型误判，也不是实局收益保证或多人不可剥削证明。两个模型内测试证明对手持续跟注／弃牌会改变八人博弈中的行动选择，并验证有利／不利候选的接受与拒绝。

## 3. 自动训练、评测、发布、回滚

服务启动后，每 30 秒检查已有采集数据库的新完整结算。一次只运行一个学习任务；原始事件和 ACK 不等待训练。核心 Pluribus 自博弈及其存储格式不变。

1. 从最近最多 160 手完整且结算配对的牌局中提取最多 8,000 条对手决策；每条都以冻结的决策前事件前缀重新执行公开下注引擎，检查行动者、金额和合法动作。本人行动不作为对手标签。未来公共牌、结算收益和未知底牌不进入特征。
2. 按结算到达顺序，以整手牌切分历史训练集和新的留出集。至少 6 手、40 条训练样本、20 条评测样本；留出集至少两手，不足时扩大整手留出范围。与已上线模型比较时，全部留出手必须晚于旧模型的数据边界。
3. 用留出集 log loss 和 Brier 同时对比均匀合法类别基线及旧上线模型。候选 log loss 必须至少改善 0.001，Brier 不得退化；不通过则保留旧版。发布的是被评测的权重，不事后用留出标签重新拟合。
4. 同一短事务保存模型摘要、数据摘要、切分边界、评测结果和活动指针。发布后新事件才可使用新模型；比较期间活动版本若改变则拒绝覆盖。最多保留 64 条训练报告及活动／回滚两个模型，每模型不超过 2 MiB。
5. 模型、活动指针和报告都在 `capture.sqlite3`，随既有 `texas-state export/restore` 迁移；公开 Serve／Client 不含私有数据。重启不重复训练同一个数据边界。

本轮真实数据副本验证：9 手、102 条通过回放的对手决策；71 条训练、31 条评测。候选 log loss **0.7672**，均匀基线 **0.9286**；Brier **0.4665** 对 **0.5968**。这是历史四人数据上的行为预测验证，不是八人推荐胜率或盈利验收。

查看本 Origin 的学习状态：`GET /v1/capture/learning`。回滚：`POST /v1/capture/learning/rollback`，JSON 为 `{"expected_version":"当前活动模型的64位摘要"}`。两者沿用本地 HTTP 边界，需要 `Origin` 与 `X-Texas-Local: 1`；令牌模式另需鉴权。错误或尚无足够数据时继续使用已验证基线。

本次闭环训练的是**进入策略求解的对手条件行为策略**，不是把人类行动当作最佳行动或把一手事实收益直接写成 CFR 遗憾。核心自博弈策略的对手池收益评测、自动质量晋级及长期会话收益仍在 R07／R04，完整真人八人验收仍在 R09。

## 可重复验证

0.8.1 修复了开局通知前可见手号已变化导致历史完整标记丢失、座位短暂消失导致观察器退出、单手校验失败后业务源永久停止。校验失败会保存缺口并等待下一次明确开局；不会将失败当手重新标为完整。存储失败、账号变化及未知执行上下文仍停止或拒绝。WebSocket 重试与 alarm 共用同一条连接，关闭后释放句柄；侧栏显示 manifest 中的实际版本。

0.8.2 贯通固定 4 分前注、以前注全下、足额 straddle 资格和单次补码 800–8000。原训练库备份后保留历史条目，新规则信息集独立，累计轮数与当前规则迭代分开展示。实采盲注延迟显示只在未见本人发牌的开局视图中按明确扣款校验，不接受任意筹码修正。规则迁移与实采核查见 [前注接入](ante-migration.md)；仍不能把输入通过当作策略覆盖。

0.8.3 将可信实采的公开开局自动加入同一自博弈库，保留原累计、RNG 和版本来源。私牌重新随机抽样，实际人类行动和单手收益不作为 CFR 遗憾标签。新增开局、平均策略覆盖及独立策略质量分别核验，详见[实采开局](observed-openings.md)。

完整 CI 另检查全部 Python／Node／Rust、真实 Python 服务与扩展的协议、程序打包、离线安装和状态迁移。合成用例和实际采集数据的证据分别记录，不以合成牌局冒充实局。

Pr1.0 搜索修正的八人翻牌合成回归：已有空历史平均时，构建范围的策略读取从 9,408 次降到 1,352 次；已有一个精确私牌平均时从 9,407 次降到 1,352 次。两种情况下所有手牌的历史似然与修正前完全一致，精确私牌覆盖不影响同桶的其他手牌。上述是读取次数验证，不是生产 SQLite 延迟或实局推荐成功率。
