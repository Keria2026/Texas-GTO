# 蘑菇游戏规则与建模边界

来源：用户于 2026-10-31 提供的“蘑菇游戏”客户端规则截图。以下为截图可见内容的转录与工程解释，尚未通过实际牌谱或平台接口验证。截图仅代表当前展示的配置，不证明所有牌桌配置相同。

## 截图已明确的规则

| 项目 | 可见规则 |
| --- | --- |
| 蘑菇缴纳额度 | 20 分 |
| 蘑菇缴纳位置 | 全部玩家，小盲位 ×2 |
| 启用人数 | 牌局满 4 人可进入蘑菇模式 |
| 人数不足 | 不足 4 人时蘑菇池冻结，人数满足时恢复 |
| 亮牌 | 赢得蘑菇池时强制亮牌 |
| 缴纳 | 所有玩家缴纳蘑菇底分进入蘑菇池；蘑菇位（小盲）额外缴纳一份底分 |
| 奖励 | 蘑菇位（小盲）玩家收池时，赢得蘑菇池内所有奖励 |
| 累积 | 非蘑菇位玩家收池时，蘑菇池奖励累计到下一手 |
| 牌局结束 | 蘑菇池剩余记分牌平均分配给参与最后一手牌局的玩家 |

“20 分”是截图所示蘑菇底分，不能据此推断大小盲、bb 换算或现金价值。若一轮缴纳有 N 名合格玩家、底分为 B、恰有一位小盲，则该轮新增蘑菇池为 (N + 1) × B；小盲缴纳 2B，其余各 B。实际缴纳时点和合格玩家集合仍需确认。

## 工程建模要求

- 蘑菇池是独立于主池／边池的跨手状态，不使用个人“蘑菇数量”或未经证实的惩罚机制替代。
- RuleProfile 保存底分、最低人数、小盲额外缴纳倍数和版本；本截图配置为 20、4、额外 1 份。配置值可变，不散落硬编码。
- mushroomState 至少记录池余额、active/frozen 状态、当前蘑菇位、参与及缴纳资格集合、缴纳账本、结算记录和状态版本。人数不足时保留池余额，不能清零。
- 跨手余额归属牌桌会话，逐手事件引用该状态；每手可重放缴纳、冻结／恢复、奖励与终局分配，事件必须幂等。
- 缴纳、奖励、终局分配分别记账。若平台筹码余额已含蘑菇转账，效用计算不能再次计入。未确认平台资金口径前分别保留可核对的账目。
- 状态守恒：期末池余额 = 期初池余额 + 实际缴纳 - 实际奖励 - 终局分配；冻结不是分配事件。
- 小盲获奖须基于明确的合格收池事件。主池／边池、多赢家或平分时规则不明，不根据“赢过任意池”自动发放全部奖励。
- 非小盲获胜后的累积会影响后续手价值，因此普通单手德州 GTO 只能作为参考。模型需考虑当前池额、位置轮转、未来缴纳、奖励资格及终局分配；模型未覆盖时明确返回不支持蘑菇策略。
- 强制亮牌只允许记录平台实际公开的牌。不能推断接口总能取得牌面，也不能将获奖前未知底牌视为已知；回测禁止用后续亮牌泄漏当前决策信息。

## 仍需确认的边界

1. 缴纳是否在每手发牌前发生；冻结期间是否停止缴纳；恢复当手如何处理。
2. “满 4 人”按入座、在场、非坐出还是实际发牌人数计算；中途退出、断线、新入座和无小盲场景如何处理。
3. 小盲与他人平分、只赢边池、只赢主池或多次发牌时，蘑菇池如何归属；无人跟注获胜是否同样强制亮牌。
4. 筹码不足时是否允许部分缴纳、全下或欠缴，以及相应奖励资格。
5. “牌局结束”的触发条件，最后一手参与者定义，平均分配的整数余数处理及是否存在费用。
6. 缴纳是否从桌上筹码扣除、影响有效筹码，以及底分与筹码最小单位的换算。

这些边界阻塞对应自动结算和策略输出，不阻塞标准规则离线核心或按明确前提构造的模拟算例。

## 后续实现的验收样例

- 假设 4 人均有资格缴纳、B=20 且有一位小盲：该轮缴纳总计 100，小盲 40，其他各 20。
- 非小盲收池后余额结转；后续小盲合格获奖时领取全部已累计奖励，不能只领取本手新增部分。
- 从 4 人降至 3 人池冻结且余额不变，恢复至 4 人不丢失历史余额；缴纳时点按确认后的规则测试。
- 终局剩余池按已确认的最后一手参与者分配；覆盖整除与有余数情况。
- 重复事件、回放及重连不重复缴纳或派彩；每次结算验证独立池账本与玩家余额守恒。
- 平分／边池等未确认情形返回规则缺失，不能静默选择赢家。

以上为验收要求和算术示例，尚无对应实现或已执行测试。
