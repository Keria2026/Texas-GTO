# 目标牌桌与蘑菇规则

来源：用户提供的客户端规则截图，以及后续对实际牌桌的直接补充及三项追问的明确答复。后续补充优先于截图；尚未用真实牌谱／接口验证。本文是需求记录，不代表当前程序已支持全部规则。结构化记录见 [目标配置](rules/wpk-eight-player-requirements.json)。

## 最新已确认信息

| 项目 | 用户提供的规则 |
| --- | --- |
| 目标人数 | 8 人 |
| 小盲／大盲 | 2 分／4 分 |
| Straddle | 每手强制 8 分，由大盲左侧（UTG）缴纳；翻前从其左侧开始行动，straddle 保留加注权 |
| Re-straddle | 用户确认允许；实际金额、顺位和链长度尚未用牌谱核查 |
| 初始买入 | 800 分，按大盲 4 分计算为 200bb；后续随输赢变化，不按手重置 |
| 金额换算 | 1 分 = 0.1 元；800 分 = 80 元；内部使用整数积分 |
| 抽水 | 无抽水 |
| 蘑菇缴费来源及时点 | 先从桌上筹码扣蘑菇费，然后缴纳盲注和 straddle；扣费后无筹码则不发牌 |
| 缴纳额度 | 每位参与游戏的玩家 20 分，小盲合计 40 分 |
| 筹码不足 | 不足支付费用或扣费后无下注筹码时不能入池，不收蘑菇费；下局前补码，否则待补码，不参与下局 |
| 不足额 straddle | 必须先补码才能参与，不按剩余筹码执行短 straddle；未补码者暂不参与，不收费用，盲位顺延，其他合格玩家继续 |
| 补码门槛 | 补码后的桌上筹码至少 400 分；不是要求每次额外增加 400，也不等于每手重置到 400／800 |
| 蘑菇获奖资格 | 小盲必须独自赢得主池；只赢边池或平分主池均不获奖 |
| 人数不足 | 少于 4 人时取消游戏，进入结算界面 |
| 结束分配 | 按各人对剩余蘑菇池实际缴纳的费用原额退还；池已被领取的旧缴费不再退还 |
| 下桌后的盲位 | 顺延；极短筹码在顺延后的资格与转账仍需处理 |

截图还说明未触发奖励时蘑菇池跨手累计，领取蘑菇池时强制亮牌。截图和用户较早答复中的“平均分配”已被最新“按自己缴费返回”覆盖。退款必须跟踪剩余池对应的各人缴费；池被领取后清空这些待退记录，因此不产生均分余数或重复退款。

截图曾写“不足 4 人时冻结，人数满足后恢复”，与最新“人数不足取消并结算”存在差异。用户已明确人数门槛为 4，目标牌桌在少于 4 人时结束结算；不能自动冻结恢复，也不能因为未满 8 人就结束。

## 金额及训练口径

- `big_blind_points = 4`、`straddle_points = 8` 必须分开保存。800 分是 200 个大盲单位，也等于 100 个 straddle 金额单位；后者仅为比例换算，不表示可以将规则中的大盲直接改成 8。
- 8 名合格参与者且恰有一位小盲时，每手新增蘑菇池为 `7 × 20 + 40 = 180` 分，即 18 元、45bb。这是新增额，获奖时还要包括前手累计余额。
- 普通玩家单次蘑菇费为 5bb，小盲为 10bb。该转账必须进入完整会话收益，不能从策略计算中忽略。
- 蘑菇池独立于当前主池／边池，只有满足资格的小盲能触发即时领取；不能把它作为所有玩家都可赢取的普通底池或前注。
- 若已从桌上筹码扣除蘑菇费，净收益不得再次扣相同费用。现金仅在展示层由整数积分换算。

初始满桌算例：每席 800 分时，先扣蘑菇费使普通席位减少到 780、小盲减少到 760；再计入小盲／大盲／straddle 三个不同席位的 2／4／8 投入后，可用余额总和为 6206，普通底池为 14，蘑菇池新增 180，合计仍为 6400。后续各手沿用实际输赢后的筹码，不能反复按 800 重建。

## 需要补齐的规则

1. Re-straddle 已确认允许，实际金额／顺位范围仍待牌谱核查。不足完整 straddle 的参与资格已按最新答复解决：先补码至至少 400 分，未补码者跳过且盲位顺延；不创建短 straddle 或虚构其跟注门槛。
2. 已确认费用在盲注／straddle 前扣，不能入池者不收蘑菇费。需将顺延后的整桌资格筛选接入会话状态机。
3. 初始买入是否还允许其他档位、补码上限；800 分初始买入、跨手保留筹码及补码后至少 400 分已经确认。
4. 坐出／断线的处理及人数统计口径；已确认待补码者不参与、盲位顺延，剩余不足四名合格玩家时结束结算。
5. 移除未达缴费门槛者后盲位顺延；顺延后的新小盲也需重新检查费用资格。
6. 结束蘑菇池按实际待退缴费返回已确认；取消进行中牌局的普通下注返还仍需核查，不能与完成一手后结束混用。
7. 小盲无人跟注赢主池是否仍强制亮牌；多次发牌若存在，其主池唯一赢家如何判定。

不能用未确认默认值生成该目标桌的可信策略。未知字段不阻塞小博弈算法验证、现有标准德州实验或独立账本测试。

## 对实现的影响与当前差距

现有标准德州引擎已支持 2–8 人，4–8 人可配置足额 live straddle，API 支持逐席筹码和第八席观察者；协议、牌力对手人数上限与训练配置已同步扩展。已加入八人行动顺序、加注权、全下边池、筹码守恒、训练导出与确定性续训测试。标准引擎仍拒绝短 straddle，蘑菇会话先通过资格筛选避免该下注状态；re-straddle 和完整长期策略尚未实现。工作台现已展示八人蘑菇有限视野的自动训练状态，Kuhn/Leduc 仅保留为开发校验。

`mushroom.py` 提供独立账本、幂等／回放、主池奖励及最终分配；显式的 `split_main_pot` 只结转。历史冻结／恢复和均分仍仅用于模拟配置，不能自动成为目标桌规则。

账本新增显式 `settlement_policy="refund_contributions"`，跟踪待退的实际缴费，领奖时清空；结束时包括已离桌缴费者在内逐人退款，重复结算与事件重放不重复转账。旧均分／冻结政策仅保留为历史模拟配置。

新增 `mushroom_hand.py` 已将资金充足的 4–8 人单手与真实桌上筹码合并核算：费用先扣、盲注后扣；小盲独赢主池领取整个蘑菇池，赢边池或平分则结转，下一手沿用实际余额。它已由下述有限视野训练模型复用，尚未用于真实 WPK 推荐；未筛选资格或短 straddle 的牌桌仍拒绝，不会用零筹码发牌或重置为 800 分绕过边界。完整长期策略仍需要更可靠的池额延续价值。

`mushroom_table.py` 将上述单手和账本合并为稳定席位的会话模拟：在手间筛掉无法缴费并保留下注筹码者，不能担任小盲者或扣费后不足完整 straddle 者进入待补码状态，盲位顺延后重新检查；不收其费用。待补码状态持续到显式补码后达到至少 400 分，不因下一手位置变化自动重新入池。少于四名合格玩家时不再扣新费用，按待退记录结算给原缴费者。支持手间显式补码和实际筹码续局，八人降到七人继续。总桌上筹码、普通底池、蘑菇池之和始终等于累计投入资金。该模块不填造 WPK 缺失状态，re-straddle 尚未接入；完整长期训练和实时推荐仍未完成。

上述资格更新进入训练规则 `mushroom-session-horizon-v2`，待补码席位也是公开状态的一部分。旧 v1 检查点不能沿用到 v2；旧规则没有版本记录的模拟会话也拒绝重新解释其事件，保留原记录。训练目前不模拟玩家主动补码，未提供补码者按已确认规则跳过；不会为了继续训练自动创造外部筹码。

`mushroom_game.py` 新增有限视野的训练接口，复用此会话模拟器并在每次反事实分支独立复制账本。它已能训练八人 800 分、跨两手延续筹码与池额的 Pluribus 检查点；CLI／API 会声明视野，终局以按缴费退款结算。该视野是近似，完整长期收益、re-straddle 和真实输入的可靠推荐仍未完成。

后续需要增加：

- 已实现的 8 人和足额 live straddle 行动状态机之上，补齐确认后的短筹码、re-straddle 和蘑菇会话规则；规则版本与训练工件绑定。
- 会话资格、补码和结束状态；蘑菇账本与桌上筹码原子转账。
- 以主池唯一赢家集合判定奖励；小盲赢边池／平分时奖励结转，不能误派奖。
- 随位置轮转和蘑菇余额变化的跨手效用；强制亮牌只在发生后成为观察。
- 在新规则下重新训练、搜索与独立评测；Pluribus 六人论文结果不证明八人蘑菇玩法强度。

## 待新增的验收样例

1. 八人缴费 180 分，桌上余额减少总数与蘑菇池增加总数完全一致。
2. 小盲单独赢主池领取全池；非小盲赢主池、小盲只赢边池、小盲平分主池均结转。
3. 普通玩家 19／20 分、小盲 39／40 分的资格边界，结合确认后的扣费顺序测试。
4. 待补码者未获得下一手底牌；补码后按已确认规则恢复；位置重排不漏扣／重扣。
5. 4 人降至 3 人进入结算；8 人降至 7 人不因该门槛触发结束。正确分配或返还，覆盖余数。
6. 新事件重复、断线重放、并发补码不造成重复扣费或派奖。
7. 强制 straddle 由大盲左侧缴纳，翻前从其左侧开始，轮到 straddle 仍有合法加注选项。
8. 连续手牌使用前手结束余额与显式补码记录，不自动重置到 800 分。

这些是新增目标验收要求；已执行的历史模块测试见 [离线验证记录](experiments/offline-verification.md)，不作为新规则已实现的证明。
