# Pluribus 主算法实现记录

最终产品目标是 4–8 人蘑菇局，以 8 人为主要场景，由 WPK 前端输入实时牌局，服务器推荐决策并承担训练。当前交付是训练主线的数学实现与小规模验证；真实牌局样本训练、模型自动晋级和目标蘑菇规则仍未完成。

## 本次实现

依据作者公开的 [Supplementary Materials](https://noambrown.github.io/papers/19-Science-Superhuman_Supp.pdf) 第 14–18 页及 Algorithm 1，新增 `texas_strategy.pluribus`，通过现有 `Trainer(..., algorithm="pluribus")`、HTTP `/v1/training` 和网页训练入口调用。

- External-sampling MCCFR：机会事件按真实分布采样，对手按当前策略采样，遍历更新玩家的动作；更新按玩家顺序生效。与原有带探索及重要性修正的 `mccfr` 对照实现分开。
- 负遗憾剪枝：每位更新玩家的遍历有 95% 概率允许剪枝，另 5% 完整探索。只跳过低于阈值且概率为零的动作；末下注轮及立即结算动作始终保留。遗憾下界允许之后恢复动作，未永久删除动作或改变合法动作集。
- 早期周期折扣：第 k 个折扣周期将遗憾和策略累计量同乘 `k/(k+1)`，到设定阶段后停止折扣。
- 策略积累：第一下注轮采用独立的动作采样计数，枚举其他玩家动作；后续下注轮周期性保存当前策略的算术累计快照。蓝图对累计量归一化，尚未积累的节点保持未覆盖。
- 工件：保存算法版本、完整配置、每个信息集的下注轮和 RNG。预算耗尽、取消或异常时丢弃整轮改动并回滚 RNG；续训与同种子连续训练逐项一致。旧 CFR/MCCFR 工件保持兼容。

## 与原文的区别

本实现版本为 `pluribus-iteration-schedule-v1`。论文使用墙钟分钟调度；这里使用**已完成的迭代数**，以便预算中断、断点恢复和实验能准确复现。迭代数不被解释为等效原论文分钟数。

| 配置 | 本地研究默认值，单位为完成迭代数 |
| --- | ---: |
| strategy_interval | 1 |
| snapshot_interval | 100 |
| average_after | 0 |
| prune_after | 200 |
| discount_interval | 10 |
| discount_until | 400，边界不含 |

`prune_threshold=-300000000`、`regret_floor=-310000000` 保留原文数值，但其尺度是模拟器的收益单位；不能直接假定对不同筹码、蘑菇收益和抽象同样合适。默认研究设置立即积累策略，区别于原文的 800 分钟预热、10000 次策略更新间隔和后续快照时间。实验可显式改变配置，但变更进入工件并绑定续训。

本实现用双精度累计值和内存中的快照累计量，尚未实现原系统整数存储、磁盘快照优化、生产级有损牌张抽象或并行训练。现有花色规范化不替代这些抽象。

## 运行

在 WSL `/home/ubuntu/Project/Texas-GTO`：

```sh
uv run --frozen texas-research train --game kuhn --players 2 \
  --algorithm pluribus --weighting linear --iterations 3000 --seed 42 \
  --max-nodes 1000000 --seconds 30 \
  --blueprint artifacts/pluribus-kuhn.json \
  --checkpoint checkpoints/pluribus-kuhn.json

uv run --frozen texas-research evaluate --game kuhn --players 2 \
  --blueprint artifacts/pluribus-kuhn.json --mode exact --require-coverage

uv run --frozen texas-research resume --game kuhn --players 2 \
  --from-checkpoint checkpoints/pluribus-kuhn.json --iterations 1000 \
  --blueprint artifacts/pluribus-kuhn-next.json
```

`--pluribus-config` 可传配置 JSON，例如 `'{"snapshot_interval":10,"prune_threshold":-10,"regret_floor":-11}'`。HTTP 训练请求使用同名 `pluribus` 对象，拒绝未知配置、非有限值、非法周期和不兼容算法。网页可直接选择“Pluribus MCCFR”，使用默认配置；选择原算法可运行对照。

## 验证与边界

八人标准德州与足额 live straddle 已接入同一 Pluribus 训练器。规则引擎保留 straddle 翻前最后行动和加注权，翻后最小下注回到大盲；逐席筹码、按钮和 straddle 金额进入规则版本。八人 checkpoint 续训与相同种子连续训练的 blueprint 校验和一致；含 straddle 的工件拒绝载入无 straddle 游戏。以下小筹码命令仅验证完整训练迭代和工件链路，不代表目标 800 分蘑菇桌策略质量：

```sh
uv run --frozen texas-research train --game holdem --players 8 \
  --stacks 8,8,8,8,8,8,8,8 --small-blind 2 --big-blind 4 --straddle 8 \
  --bet-fractions none --algorithm pluribus --iterations 1 --seed 42 \
  --blueprint artifacts/eight-straddle-smoke.json \
  --checkpoint checkpoints/eight-straddle-smoke.json
```

最终目标仍需长期蘑菇会话的延续价值、单一核心策略库的实局状态匹配、基于可靠 WPK 状态的限时搜索和推荐推送，以及真实样本与独立质量评测。空闲自动续训已接入下述有界研究候选；现有原始牌张／花色规范化的稀疏表不能作为成熟策略库自动用于真实牌桌。

旧研究配置对八人 800 分、2/4 盲注、8 分 straddle 的标准德州基线进行预算检查：`SuitCanonicalHoldem`、Pluribus、种子 42、10 万节点／3 秒上限，请求一轮，实测 28,560 节点后超时，完整迭代为 0。根因是每轮都枚举翻前平均策略；采用原文的 `strategy_interval=10000` 后，同种子首轮为 1,345 节点、约 0.12 秒，完整迭代 1。后续到达策略积累周期仍需支付枚举成本；该优化不表示策略覆盖或质量达标。

新增 `MushroomSessionGame` 已将会话状态接入同一个 Pluribus 训练器：4–8 席、实际筹码、池额与缴费归属延续，公共历史和各自私牌记忆分离，小盲领奖后才公开其牌。视野末尾或合格人数少于四人时按待退缴费结算，终局收益取各席净筹码变化，费用不重复扣除。视野是明确的训练近似，不能将两手模型当作完整长期会话策略。

资格更新前的 v1 模型：八人各 800 分、两手视野、种子 42、`strategy_interval=10000`、`snapshot_interval=1` 的实际两轮训练为 46,766 节点、约 6.58 秒，生成 19,736 个遗憾信息集和 19,649 个平均策略信息集，检查点 5,728,646 字节。信息键对完整公共状态／历史使用 SHA-256 摘要，保留各自私牌记忆，避免在每条策略中重复保存整段公开 JSON；这不是牌力有损分桶。默认快照周期仍为 100，此实验显式缩短周期以验证工件链路。

`test_mushroom_training.py` 用上述八人 800 分模型验证连续两轮与一轮后保存／加载再续一轮的校验和一致，拒绝跨视野加载。新 wheel 已在脱离源码目录的独立虚拟环境中安装，完成跨手训练、检查点恢复与 HTTP 健康检查。它证明后端和工件可移植运行，不证明扑克策略强度。

`engines/strategy/tests/test_pluribus.py` 检查剪枝及恢复、末轮/终局例外、所有遗憾为负时保留概率质量、折扣数值、翻前计数与翻后快照、Leduc 续训、预算回滚和实际德州精确发牌采样。4–8 人隐藏行动有限博弈检查信息边界、玩家收益向量与训练输出；它们不等于 4–8 人德州或蘑菇牌局。

Kuhn 用独立最佳响应评测，并验证 blueprint 保存加载后进入全范围、多后续策略搜索。服务测试覆盖训练提交、工件读取和节点策略查询。实验结果见 [本次实验](experiments/pluribus-core.json)。

`core_training.py` 已将八人各 800 分、两手蘑菇模型接入独立进程自动训练。单一检查点每个完整迭代保存，空闲恢复不重做暂停中的遍历，服务重启则确定性恢复最后保存进度。`test_core_training.py` 对真实目标筹码模型检查暂停／续训后的完整 JSON 字节（包括遗憾和 RNG），以及单写入者、尺寸上限保留旧结果、损坏导入不重置、服务生命周期和采集优先级。调度不降低训练质量门槛，`recommendation_ready` 仍为 false。

持续自动训练在旧 v1 第 8 轮暴露了第二手筹码 `(644,624,776,772,24,338,780,2262)`、按钮 1 的入局缺口：席位 4 扣费后无法支付完整 straddle。用户随后确认必须先补码至至少 400 分，否则跳过、盲位顺延。新 v2 在扣费前反复筛选并持续记录待补码席位，不会自动给该玩家增加筹码；回归测试覆盖该具体状态、连续短筹码顺延、四人降三人结束以及补码后重新入局。规则变化使 v1 工件不再兼容，旧检查点需要保留归档而不能冒充 v2 续训。

本机 systemd 服务实测已启用 v2 自动训练，超过原故障轮次；在第 17 轮因计算请求进入暂停，接口该次约 22 毫秒返回（不是 p95 指标）。服务重启后由新 worker 恢复同一份第 17 轮检查点，SHA-256 不变，空闲后继续到第 18 轮，随后已保存到第 20 轮。旧 v1 七轮工件保存在 `artifacts/local/core/archive/rules-v1-hnkx4lr0`，未删除。CLI 导出并加载 v2 的完整训练状态已验证；早期平均策略为空时导出的 blueprint 仍不具备推荐覆盖。新的 wheel 在源码目录之外的独立虚拟环境中自动训练并保存 v2 检查点，证明进程入口也随包移植。

本轮完整检查为 501 项 Python 测试、11 项 Node 协议测试、TypeScript、schema 一致性、Vite 构建和 Ruff 均通过。浏览器检查覆盖 320／390／1280 像素、开发工具展开、状态读取失败、离线清除过期进度和恢复重连；设计检测器仍提示沿用的字体／小字号与营销参考的差异，未据此改造既有界面。上述验证不代替真实 WPK 对局和策略收益评测。

## 八人搜索的抽样后续评估

在补充材料第 23–24 页的多后续策略结构上，新增 `sampled_rollouts=True`：仍然让所有活跃玩家（含 hero）隐蔽选择后续策略；之后沿所选联合策略抽样行动和发牌，由完整终局返回所有席位的净积分。使用现有带重要性修正的 external-sampling MCCFR 训练搜索子博弈。抽样 RNG 归训练器管理、未完成迭代回滚；不把首次随机收益固定为叶值。原精确尾值路径保留作独立对照。此项是工程实现，不声称完全恢复作者未公开的实现细节。

独立检查覆盖机会概率、完整树期望、策略选择不可见、零概率动作、缺失 blueprint、节点／时间限制、取消后的遗憾和 RNG 一致性。八人 800 分两手测试在禁止枚举牌张机会事件的条件下完成，保留人数不足提前结束和原额退款规则。当前实验与源码哈希见 [sampled-search.json](experiments/sampled-search.json)，复现入口为 `training/verify_sampled_search.py`。

八人试验使用调用者提供的八个合成隐藏世界及均匀后续策略；这只验证抽样搜索和规则能够一起运行。它不是完整公共信念、实战训练模型或 WPK 行动建议。抽样搜索约 10.39 秒完成 32 轮，距离当前实时目标仍有差距；未知范围、策略覆盖和总体误差不能因获得一个动作分布而省略。

加入此能力后完整检查为 513 项 Python 测试、Ruff 检查与 96 个 Python 文件格式检查通过；新增 12 个测试用例。更新后的 wheel 在源码目录之外的独立虚拟环境完成 500 轮抽样搜索、6,000 条后续轨迹，无 blueprint 回退。本轮未修改前端或协议，未重复浏览器验收。

同一时段，既有核心自动训练实际保存到第 147 轮后触及 64 MiB 工件上限，工作进程以 `limited` 结束，HTTP 服务继续在线。完整检查点为 67,070,458 字节，重新加载通过校验，含 202,905 个遗憾信息集和 133,717 个已积累平均策略信息集。下一轮未覆盖旧检查点。该结果证实当前完整牌张／历史表格会迅速耗尽容量；尚未解决信息集抽象和长期持续训练，不能用达到 147 轮冒充成熟策略或通过反复重启掩盖同一限制。

实时搜索现有实现仍是有限博弈验证台，尚缺完整德州的可扩展公共根构造、下注轮起点重求解和生产质量评测。普通德州已支持 2–8 人及足额 straddle，蘑菇有限视野模型已接入训练；下一步仍需长期会话建模、re-straddle、实局匹配并独立评测。真实牌谱可用于回放、条件行为模型和独立评测；不会把未走过动作的收益当作已有真实标签，也不会未经评测自动替换基础策略。

## 可复用上下文与检查点存储

新增 `abstraction=mushroom_context`，使用相对位置、当前手行动、筹码档、翻前 169 类和各街 200 个可见牌聚类。牌张特征与码本为本项目的合成数据实现，未取得作者原始配置。已结束牌局的经济影响继续进入状态，但历史记忆被压缩，属于明确的不完全记忆近似。在线搜索保留实际持牌标识，API 将抽象下注标签映射回当前局面的合法积分金额；没有覆盖的节点仍拒绝推荐。规则绑定、确定性码本构建和独立验证范围见[上下文模型](mushroom-context.md)。

新 checkpoint schema 2 只减少重复字段／动作列表，保留全部双精度累计值、下注轮和 RNG，并继续导入 schema 1。策略可以跨相近筹码局面查询，续训则另用 `training_context` 固定起始筹码和按钮。旧完整记忆模型与新分桶模型的遗憾不能直接合并。此历史基准使用旧的 10000 轮翻前平均策略间隔，周期之前该下注轮没有平均策略覆盖；后续快照数量不能代替翻前覆盖。

本机新模型独立完成 200 轮，278,622 个遗憾信息集。相同训练数据从 81,263,532 字节缩为 50,069,929 字节，默认 64 MiB 限制内恢复，并逐项验证下一轮结果一致。旧完整记忆 147 轮已归档，服务已恢复新模型并自动保存第 201 轮。543 Python／11 Node、类型／schema／构建／Ruff 和独立 wheel 进程验证通过。该变化增加了可保存进度，没有消除表规模增长或完成实局匹配；实测和限制见[实验记录](experiments/mushroom-context.json)。

## 采样平均策略扩展

新版本 `pluribus-sampled-average-v1` 保留遗憾遍历、剪枝、折扣和后续下注轮快照，只替换第一下注轮的平均策略积累。旧 `pluribus-iteration-schedule-v1` 和原八字段配置继续按原算法恢复；新蘑菇模型默认每轮每席 16 条路径，小博弈默认仍为原枚举算法。这是本项目在作者补充材料第 17 页 UPDATE-STRATEGY 基础上的采样改造，不是原文已实现的功能，也不提供八人均衡保证。

对固定策略，原平均过程的期望累计为 `sum_h pi_chance(h) * pi_i(h) * sigma_i(I,a)`，其中同一信息集内的对手历史逐一计数。新过程按真实概率采样机会、自身按当前策略采样，对手按合法动作均匀采样。到自身决策时，仅使用此前对手动作提议概率乘积 `Q_opp(h)`，给各动作加 `sigma_i(I,a) / (samples * Q_opp(h))`。不除机会或自身到达概率，不乘对手当前策略，也不使用未来路径概率。全向量更新是原自身动作计数的条件期望，随后仍采样自身一个动作继续。

独立解析测试用非均匀机会、自身重复决策、对手零概率动作、变化的分支数和同信息集隐藏历史，枚举采样空间并与 14 个动作的精确期望比较。对其中一个动作，单路径二阶矩从抽单动作的 `5/9` 降为条件期望更新的 `10/27`；这不是实局收益或整体方差的评估。深层前缀权重仍可能很大，非有限值直接报错并回滚，不截断权重来掩盖偏差。

平均随机流由版本、训练种子、迭代、席位和样本编号确定，独立于遗憾训练 RNG。中止重试和 JSON／SQLite 续训可复现，改变平均样本数不改变遗憾采样。两手蘑菇模型只对 `stage=0` 使用此平均，第二手翻前的 `stage=4` 仍走既有快照，不暗改训练目标。

已有 SQLite 库可以显式升级，但必须先停止训练并备份；升级只允许第一下注轮平均全为零的旧模型，原遗憾、平均数值、轮数与 RNG 均保留，`sampled_average_from` 记录从下一轮开始积累。已有非零翻前平均时拒绝升级，避免未经重加权混合不同采样周期。该改造只解决可计算的平均积累，覆盖率、留出评测、可信 WPK 状态、画像适应和实时推荐仍需分别接口已实现，未接入实采验收。

## 生成式公共根（算法）

固定一个公共根，令其未归一目标质量为 `w(h)`、提议分布为 `q(h)`、总质量为 `Z`。当提议覆盖所有正目标世界且能准确计算自身概率时，初始根采样可使用 `sampling_reach=q(h)`、`ratio=w(h)/q(h)`。冻结策略下一步遗憾的期望等于归一目标 CFR 的统一 `Z` 倍，原始平均累计保持现有 `own/sampling_reach` 形式。不能把平均累计再乘 `w/q`；随机累计归一化后的策略也不保证有限样本无偏。这是本项目数学研究，不是作者未公开实现的复现。

三人五牌、60 个合法私牌世界、非均匀范围及未来发牌、六次玩家决策的 Fraction 枚举，逐项检查 2310 个遗憾／平均坐标，全部精确一致；独立复核另检查 0／1 行动概率和零质量根。错误的阻断牌概率、漏遗憾权重、错误平均权重、只保留实际 hero 手牌及继续累加零质量世界均有反例。本机脚本、报告和推导保存在 `/home/ubuntu/Project/work/public-belief-study/`，运行 `.venv/bin/python /home/ubuntu/Project/work/public-belief-study/verify.py` 可复核；这些不是八人实局样本。

`sample_chance_outcome` 继续只接受真实归一机会概率。新增的 `sample_training_root(rng) -> (child, q, w)` 仅用于局部 MCCFR 初始根，每位遍历者每轮抽一次；零质量样本不累加也不重抽。取消、预算或非法权重会回滚半轮累计和 RNG。该缩放只适用于同一固定根，带此来源的 Trainer 不能通过 checkpoint／blueprint 导入导出混入核心库；普通 CFR、MCCFR 和 Pluribus 路径及原工件版本不变。

`search.SampledRoot` 与 `solve_generated_subgame` 支持不保留隐藏世界列表的生成根，沿用隐蔽多后续策略及完整轨迹抽样。调用方提供目标信息键而非包含未知对手牌的假状态；没有训练到实际目标、基线覆盖不足或超时会明确拒绝。诊断提供抽样次数、正权重次数和重要性权重 ESS，但不虚构世界总数、归一到达概率或积分 EV；ESS 也不是收敛或误差证明。

`mushroom_belief.MushroomFirstHandRoot` 把模型窗口第一手的完整公开轨迹转换为上述根。按动作发生前的信息查询固定策略快照，逐席预计算所有与已知公共牌兼容的私牌 likelihood，再无放回生成全体参与者私牌；本人和已弃牌玩家都保持随机。已知公共牌只用于排除冲突，历史策略特征不提前看到后续牌面。每席固定最大对数权重仅改变该公共根的共同尺度，正权重下溢明确失败，不截断也不伪装成零概率。缺策略与树外行动属于未知覆盖。构造、采样和搜索共用取消／总时限，后续模拟保留原两手视野。

该构造器保证给定模型首手内部一致，真实牌桌的账本、参与资格及窗口锚点仍须由服务先验证；不能以构造器成功代替实采事实核验。后续模型手包含前手私牌记忆，当前不以空历史代替，尚需跨手联合范围。合成八人、800 分、两手模型的 3 轮／24 次根抽样验证到达第二手，独立完整引擎对照覆盖位置、资金、公开键、非均匀 likelihood 和已弃牌阻断；这不是已训练八人实局策略或收益验收。

### 当前手牌的重点抽样

`MushroomFirstHandRoot.solve` 使用一半原均匀联合发牌、一半以当前行动者的真实两张牌为条件的发牌提议。令剩余牌数为 N、均匀联合概率为 p，则世界 h 的完整提议密度为 `q(h)=p/2 * (1 + C(N,2) * 1[hero_pair(h)=observed_pair])`，无论实际从哪个分支抽到，均使用这一个混合密度。公共后验目标仍为原来的 `w(h)=p*likelihood(h)`；非重点世界的 `w/q` 可以大于 1，不截断。所有玩家范围及弃牌阻断保留，零目标质量不重新抽样。未指定目标的 `root.sample` 保持原均匀提议与随机序列。

这增加有限预算内实际目标信息集被访问的机会，不改变目标公共博弈，也不是 Pluribus 原文的实现声明。独立枚举三人八牌的全部 2,520 个世界，核对三个目标位置、两种抽样分支的密度、总质量和加权期望；八人测试同时验证后验不变、阻断、零质量、权重大于 1、实际目标键以及取消。历史 likelihood 每个公开动作只查询一次相同抽象键：合成翻前单动作的 SQLite 接口查询从 1,326 次减少为 169 次，不跨快照缓存或猜测未训练节点。

只读实库第 5899 轮检查中，合成八人 800 分的开局及跟注一次后的搜索仍因缺少后续平均策略而明确失败，未使用均匀补齐。证据位于 `/home/ubuntu/Project/work/focused-search-check/live-policy-probe.json`。该优化尚未接入实采推荐，不能以合成完整策略测试成功声称真实策略库已支持在线搜索。
