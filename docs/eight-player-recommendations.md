# 八人局行动建议：0.7.1 预览

本版接通 WPK 业务事件 → 公开下注回放 → 已训练平均策略查询 → WebSocket 推送 → Chrome 侧栏。它是 V1.0 的可部署预览，尚未完成真实八人牌局和策略质量验收。用户已选择稍后开始八人实局，先完成代码与插件包。

## 建议的实际来源

查询同一套 Pluribus 自博弈核心的 SQLite 平均策略。每次查询固定一个已提交快照，返回模型摘要、累计迭代数和规则版本；不使用当前遗憾替代平均策略，不用均匀分布补齐未训练节点。模型使用两手视野、手牌与筹码分桶。0.7.0 的插件协商 `capture_search_v1` 后，翻前使用平均策略，翻后从已验证的公开状态尝试全范围、深度受限 MCCFR 搜索；画像仍只展示统计，不调整行动。

推荐包含全部动作的策略频率，并按该分布稳定抽取一次主建议。同一来源、牌局、信息集和模型版本使用相同的随机分位数；限时搜索若完成轮数变化，策略分布及最终行动仍可能变化。频率不是胜率，模型迭代数不是质量认证。

0.7.1 增加最低反馈检查：在同一个 SQLite 只读快照内，若当前节点平均为均匀分布且遗憾全部为零，不再发送行动，返回 `strategy_feedback_unavailable`；插件显示“当前局面的训练反馈不足，暂不推荐行动”。非均匀历史平均可保留过去的反馈，当前遗憾全零不等于从未访问，因此不会单凭全零拒绝这种历史平均。真正训练过的节点也可能最后变为均匀平均与全零遗憾；没有访问溯源时无法与初始化区分，所以这是保守阻断，不是训练历史证明。非均匀也不证明收益反馈充分。该检查不测量置信度、收敛或收益，查询仍输出平均策略，不用当前遗憾代替频率。

此检查也适用于翻后搜索因缺覆盖／预算不足而退回的 baseline；搜索实际成功时可使用新求解结果，不要求当前节点已有上述证据。损坏的遗憾数据仍报模型错误，不能借非均匀平均或搜索降级掩盖。数据库格式、历史训练数值和推荐消息 schema 不变。

第 6129 轮实库的[合成查询记录](experiments/feedback-coverage.json)：八人各 800 分开局，沿连续跟注的八个行动位置各查询 169 类手牌，平均策略覆盖为 `[169,169,169,149,90,64,57,63]`，通过最低反馈检查为 `[169,161,88,21,3,0,0,0]`。该结果只表示此组公开前缀的现状，不能推广到其他筹码／历史，更不是八人实采或策略强度验收。

## 输出前的条件

- 本手八个物理座位都已确认缴费并参与，明确 20 分普通费用、40 分小盲费用以及 2/4/8 强制下注。完整八席下，由小盲的前一席唯一确定按钮。
- 已观察开局快照及完整行动序列，公共牌、当前行动者和现金通过公开规则引擎回放；轮到本人且两张手牌已知。
- 从同一 Origin／source、截至当前事件前缀的不可变结算重建逐人蘑菇权益。侧栏仍仅展示最近八手，后端按手号流式读取历史，较早的整池奖励锚点不会因离开展示窗口而丢失。漏手或未配对结算仍须新的可信整池奖励恢复账本；已知金额冲突不能被后来派奖掩盖。
- 以实际开局现金和旧权益建立新的两手计算窗口，按共享信息编码查询平均策略；缺失节点、动作不一致、资金冲突或不支持的强制下注均不给建议。
- 客户端可选动作须与引擎相容。WPK 原始 min/max_raise_reported 的口径尚未确认，不能作为实际 raise_to 使用；金额由已验证引擎计算。

当前不承诺覆盖 4–7 人参与、re-straddle、所有筹码／旧池组合、任意树外下注、长期蘑菇价值或所有翻后节点。特别是这些条件失败时，插件显示原因与空动作，而非“最优”建议。

## 协议与失效

双方通过 `capture_recommendations_v1` 协商独立的 `capture.recommendation` 消息，schema 为 `tgto.capture-recommendation/0.1`。旧版 `capture.state` 观察协议保持兼容，其 unsupported 字段不代表新推荐消息的状态。

建议绑定 source_id、hand_id、through_sequence。ready 包含 actions、selected_action、model、issued_at_ms、expires_at_ms、elapsed_ms 和 warnings。每项动作包含 action、label、probability、amount_delta（本次额外支付）和 raise_to（本街总额，仅加注／下注）。不输出未知 EV。

服务先提交并 ACK 事件，再查询策略；查询结束再次检查来源的最新版本。旧批次、未 ACK 的结果、换手、换来源、当前行动者变化、停止采集、断线和过期结果都不能继续显示。快照超过 15 秒不输出建议。原策略查询总预算为 500 毫秒，协商后的翻后查询总预算为 2 秒，其中搜索最多 1.5 秒，单条建议最长有效 10 秒。插件收到业务变化即时清除建议，另每 200 毫秒检查到期。

0.6.1 将推荐计算与接收循环分开：每个连接最多一个在算任务和一个最新待算版本，新业务事件合作取消旧计算并替换待算版本；计算期间仍处理 ACK、状态和心跳。断线或协议错误会取消并回收计算，取消不能降级为成功建议。侧栏按钮刷新、定时刷新和事件刷新共用版本校验，迟到响应不能恢复旧建议。协议不变，0.6.0 客户端仍兼容。

后台 worker 重启会结束旧采集 epoch 并保留缺口；只有当前浏览器会话中仍保存了明确采集意图、原来源和同一个允许访问的标签页时，才建立新 epoch。明确停止后不会恢复；新 epoch 仍须等待完整牌局和可信蘑菇账本。页面导航仍停止采集。

## 翻后限时搜索

新插件与本版本 Serve 配套更新。旧插件只声明 `capture_recommendations_v1` 时保持原消息字段及平均策略路径；新插件额外声明 `capture_search_v1`，接收 `pluribus_search` 来源与 `model.search` 诊断。新插件不保证连接不识别此能力的旧 Serve。

在同一 SQLite 快照内重建各席的策略诱导范围，保留 hero 全范围、弃牌者阻断和完整联合发牌提议；已观察的动作只使用当时可见牌。搜索仍使用研究层的两个玩家决策深度、隐蔽多后续策略和完整两手终局净积分。最多请求 100 个迭代、30,000 个训练节点及 30,000 个尾部节点，不使用未训练节点的均匀补齐。此深度／根位置是本项目的近似，并非原 Pluribus 从街道起点重求解的完整复现；作者算法见[补充材料第 19–24 页](https://noambrown.github.io/papers/19-Science-Superhuman_Supp.pdf)。

搜索预留最多 50 毫秒给最终策略转换；训练时间先到时回滚未完成轮次与 RNG，仅使用已经完成的迭代。根构造、尾部、最终输出仍检查共同总期限与取消。`complete` 仅表示获得预算内的有效迭代结果，诊断同时返回实际轮数、训练节点、尾部节点、根抽样数、耗时和停止原因，不表示收敛。少量迭代的结果可能仍十分稀疏。

覆盖不足或搜索预算未产生可用结果时，仅可返回同一快照中已覆盖的当前节点平均策略，并标注 `coverage_missing` 或 `budget`；没有基线时返回空动作。状态变化、断线取消、总时限过期或模型错误不能回退为成功建议。侧栏显示实际来源及这些限制，不展示未知 EV。

## 已执行的验证

- 后端合成八席开局覆盖所有八种按钮旋转、具体投入与加注总额、缺平均策略、资金／行动冲突、过期、版本复核及旧客户端协商。
- 插件验证严格协议、ACK、过期、断线、迟到结果和来源隔离。跨仓库测试经过真实 Python WebSocket／SQLite、WASM 验证和持久队列；该测试模型明确使用合成权重，验证链路而非策略强弱。
- 现有真实自博弈库第 5850 轮的只读检查：合成“八人各 800 分、无旧蘑菇余额、翻前第一个决策”中，169 类起手牌全部命中，查询 p95 为 2 毫秒。仅代表这个场景，不能推广到整场牌局。
- 安装插件的 Chromium 验证金额显示、320/390/600 像素侧栏、断线／过期清除及采集恢复。后端 wheel 在源码之外验证，不使用 Windows 依赖。
- 0.6.1 用故意阻塞的计算验证心跳、新批次确认、只保留最新待算版本、旧结果丢弃、断线清理与只读快照释放；浏览器验证迟到的手动刷新不能恢复已清除建议。实际训练库第 5899 轮的合成后续搜索仍缺策略，当时研究层的重点抽样优化尚未接入推荐。
- 长历史账本使用既有学习库的不可变结算，不新增数据库格式；按事件序号限定可见记录并保持 Origin、source、牌桌隔离。5,000 手费用累计、迟到结算不得修复早先决策、历史冲突、缺手恢复和取消均有回归。合成八人第 12 手在锚点已离开侧栏窗口时仍完成真实 SQLite 策略查询；这不是实局覆盖或收益验证。返回的近期账本证据最多 17 条，完整历史仍在数据库中。

新增检查覆盖翻后真实公开规则回放、能力协商、搜索结果与基线区分、严格缺失处理、取消和总时限。软截止测试逐项比对完整迭代与中止重试的累计值、RNG；UI 校验搜索诊断与来源，拒绝不一致消息。这些均为合成验证，不是八人实局质量验证。第 6054 轮实库对 24 个合成翻前搜索探针均缺后续信息集，仍需扩展并评测训练覆盖。

本地 API 和训练子进程继续受 systemd 合计 1 GiB 上限约束。真实八人实局成功率、整体延迟、策略收益和剥削层仍待验收；本版不得标为 V1.0 完整上线。
