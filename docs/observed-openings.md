# 0.8.3：从可信实采扩展同一套自博弈训练

服务在已有的后台学习循环中，每次最多检查 64 个新的本人行动快照。只使用该快照当时的事件前缀和蘑菇账本截止点；完整公开回放、八人参与、前注规则、筹码和权益全部通过后，提取本手扣费前的公开开局。新增开局只包含逐席筹码、未退蘑菇权益、待补码席位和按钮，不包含本人牌、对手牌、昵称、实际行动标签或事后收益。所有私牌仍由自博弈重新随机发出。

收集结果保存在 `capture.sqlite3`，按来源／手号避免重复收录，同一种公开开局只占一个训练入口。历史中断仍阻断输入；同一手后补的 `hand_started` 不能抹掉早先缺口；迟到结算只允许影响其到达后的新快照。读取与提交分开，提交校验处理游标，取消或失败不推进游标。已有原始事件不改写。

## 同一核心库的分布更新

空闲 worker 在完整迭代之间读取新开局。第一次扩展前，保存独立的 `before-openings-*.sqlite3`；随后在一个元数据事务中更新开局分布，保留全部条目、配置、累计轮数和 RNG。后续扩展追加明确的迭代／开局数量记录，不为每手复制整个大库，也不删除旧开局或旧累计。

新 manifest 为 `mushroom-population-observed-v3`，保留最初的完整来源 context 和追加记录，仍使用相同的前注规则、信息编码和同一张策略表。来源开局权重保持不变；不同实采开局均分约等量的机会质量，因此默认核心约一半用于原有分布、一半用于实采分布，不按重复快照数加权。原有累计作为热启动，不重新解释成来自新分布的样本；这项课程更新不是论文固定开局分布的原样复现，也不提供新的多人收敛保证。

最多收集 512 种不同实采开局，总训练开局仍限制为 1024。达到容量后保留已收录数据和训练进度，状态明确报告新增组合尚未纳入。工作台显示训练开局数、其中来自实采的数量及容量状态；这些数字不是信息集覆盖率，也不是每个开局已训练的次数。

`texas-state export/restore` 同时保留核心 context／累计／RNG 和采集库中的开局记录／游标。只有模型 checkpoint 的独立导出也包含已经采用的完整开局分布，可确定性续训；私人原始事件与开局金额不进入公开 GitHub 程序包。

0.8.2 及更旧的程序不能续训新的 observed manifest。回退需要配套的升级前备份和旧程序，保留当前库作为归档；单独切换程序并不等于恢复旧训练状态。

## 验证与仍未解决的部分

测试覆盖只保存公开财务、座位旋转、来源隔离、迟到结算、重复／中断事件、取消、容量、更新失败回滚、自动收集并自博弈，以及 JSON 和 SQLite 导出后的确定性恢复。验证入口：

```bash
uv run --frozen pytest engines/strategy/tests/test_observed_population.py \
  services/analysis/tests/test_capture_openings.py
```

2026-11-03 本机独立安装的 0.8.3 服务已从原有 4276 条事件自动提取 3 手、3 种可信八人公开开局，并在同一核心库中从 489 扩展至 492 个开局。升级前备份的完整元数据与 RNG 核对一致，原有 6341 轮保留；观察到分布切换后的 RNG 不变，并实际保存到第 6342 轮。采集原文哈希全部保留，1 GiB 内未发生 OOM，免令牌握手通过。代码 CI 通过 1223 项 Python 检查及浏览器、离线安装迁移检查，见[部署与覆盖证据](experiments/observed-openings.json)。

API 重启约 4 秒；大库全量校验、首次备份、切换与首轮续训验证合计约 13 分钟。服务接口恢复与核心训练恢复是两个阶段，启动中显示的临时 0 轮不能当作数据库已重置。

在第 6346 轮对相同历史输入做只读核验：9 个可建模决策对应的公开开局均已纳入训练，但 9 个信息集仍全部缺平均策略。这些记录参与了开局选择，不能作为独立质量留出集；仍需核验收益反馈、全范围后续覆盖与搜索时限。

先前 9 个可建模实采决策中有 4 个含树外历史下注，本功能不改变动作树，不能靠增加开局消除这项缺口。继续执行 R02／R03 的树外处理和有效反馈评测；用来选择训练开局的同一批记录不能再冒充独立策略质量验收集。
