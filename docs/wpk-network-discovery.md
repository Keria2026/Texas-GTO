## 在已有浏览器会话中采样

1. 在自己的 Chrome 中正常登录 WPK。登录完成后打开开发者工具 → **Network**，清空旧记录，开启 **Preserve log**。
2. 打开要查看的牌桌或历史牌谱，记录一次状态加载及后续行动。分别观察 **Fetch/XHR**、**WS**；若出现流式 HTTP，也保留相关请求。不要把过滤后的列表误认为所有通信。
3. 导出包含响应内容的 HAR，优先使用浏览器的脱敏导出选项。原始 HAR 仅保存在本机；即使浏览器移除了 Cookie，响应或请求正文仍可能带账号信息。
4. 在本项目目录运行：

   ```sh
   uv sync --frozen
   uv run --frozen texas-wpk-inspect /path/to/wpk.har --out artifacts/wpk/endpoint-report.json
   ```

   分析器仅使用 Python 标准库；没有安装项目依赖时，也可用 Python 3.12 直接运行 `python adapters/wpk/src/texas_wpk/inspect_har.py /path/to/wpk.har --out artifacts/wpk/endpoint-report.json`。

5. 查看报告，再分享所需内容。报告包含请求方法、去掉查询值的 URL、查询参数名、响应 JSON 字段路径与类型、是否发现 WebSocket 记录。它不输出请求头、Cookie、请求正文、响应字段值或 WS 消息正文；常见数字／令牌路径段会替换，但任意路径名称和动态 JSON 键仍需人工检查。
6. **HAR 不保证包含 WebSocket 消息。** 若实际发现 WS，单独在该连接的 Messages 面板查看消息，提供与牌桌状态、行动、结算相关的少量脱敏示例及先后顺序。二进制消息先记录类型和长度，再结合网页公开加载的协议定义核查，不把乱码当 JSON。

只需先提供结构报告来定位接口，无需分享登录密码、Cookie、Authorization、会话令牌或整段登录请求。工具对输入大小、响应长度、深度和字段数设有上限，截断会在报告中标记；报告不是完整协议说明，也不保证自动匿名化。

## 需要核实的数据与归约关系

以下是内部需求字段，不是声称 WPK 已存在的字段名：

| 数据 | 后续内部用途 | 证据要求 |
| --- | --- | --- |
| 会话／桌号／手号 | 隔离牌局与事件去重 | 同桌多手与切桌样例 |
| 座位、位置、参与状态 | 行动顺序与小盲资格 | 初始状态及座位变化样例 |
| 筹码、底池、本街投入 | 整数账本、跟注额与边池 | 金额单位、增量／累计口径、结算样例 |
| 公共牌、本人底牌、已公开摊牌 | 牌力、范围和信息集 | 仅映射当前玩家有权看到的信息 |
| 行动、下注尺寸、事件序号 | ActionEvent 与 GameState 归约 | 完整行动序列、重连／重复消息 |
| 蘑菇池、冻结、缴纳、派奖 | 跨手独立账本 | 与已记录截图规则逐项核对 |

拿到样本后，先给每个已确认端点或消息类型记录来源、版本、字段和语义，再实现 `adapters/wpk` → 标准事件的转换。保留原始事件的本地证据索引；遇到金额不明、漏序号、缺失规则或未知事件时停止策略输出。接口抓取能力与 Pluribus 算法验证分别验收。

## 本轮交付边界

已提供采样流程、离线结构分析命令与合成数据测试。没有增加扩展的网站权限、注入页面、重放鉴权请求、自动下注或取得真实牌桌数据。真实 WPK 协议接入要以网站可达和脱敏样本为下一步输入。
