# 蘑菇局上下文抽象

`abstraction=mushroom_context` 为有限视野蘑菇模型提供可复用的信息集。真实牌张、整数筹码、合法下注、边池、蘑菇缴费／派奖／原额退款仍由 `MushroomSessionGame` 结算；策略查询使用下面的近似表示。它是研究模型，不构成实局策略质量认证。

## 同一策略如何匹配不同局面

- 翻前按 169 种私牌类；翻牌、转牌、河牌各用 200 个聚类。分桶只读取自己的牌和当时可见公共牌。
- 当前手保留按顺序发生的行动；标准下注使用最小加注、半池、满池和全下标签。标签映射回该局实际合法的 `raise_to` 金额，相同金额不重复形成动作。未在抽象树内的实际下注保留原金额，不擅自舍入成已训练动作。
- 相对按钮描述位置，分别保留每个席位的筹码档、缴费归属、待补码状态、参与／弃牌、当前投入及加注权相关状态；池额和最小加注等也进入上下文。细小强制下注与关键扣费边界保留，较大金额使用明确的粗档位。
- 已结束手牌的详细行动及私牌记忆不进入下一手的信息键；其对余额、蘑菇池、退款归属、资格和位置的影响仍存在。当前手的早先牌张桶也不单独保留。因此属于**不完全记忆的有损抽象**，不能沿用完美记忆 CFR 的收敛保证。

例如同一可见局面下，800／801 分起始筹码可以命中同一策略；扣除 20 分费用后的全下仍分别为 780／781 分。400 分局面不会因此获得同一节点的覆盖。上述例子已有 API 与规则回放测试，但不证明这些档位在策略收益上足够准确。

规则版本绑定分桶版本、码本校验和、金额边界、动作定义、会话视野和结算规则。起始筹码和物理按钮成为策略查询上下文；checkpoint 的独立 `training_context` 仍绑定训练起始配置，防止续训时静默更换分布。人数、视野或抽象配置不同仍拒绝混用。旧完整记忆检查点不能直接转成新信息集的累计遗憾；切换时必须保留旧工件并从新模型自己的训练结果开始。

## 从已有蘑菇池开始一个计算窗口

`MushroomSessionGame(stacks, button=..., outstanding=..., waiting_for_top_up=..., horizon=2)` 可接受**本手扣费前**的现金、逐席未退缴费和待补码名单；每个席位代表稳定的同一玩家，包括本手不参与者。`outstanding` 必须覆盖全部席位，池额等于其总和。已有缴费不再次从现金扣除，本手费用仍按原规则缴纳；等待者的退款权益保留，权益不能用于下注或满足补码门槛。窗口内换人、引入外部补码和 re-straddle 仍未建模。

窗口收益为 `最终现金 −（期初现金＋期初未退缴费）`。原额退款不是新增盈利，小盲获奖后清空的旧缴费也不能再次退款。对同一固定窗口，这与现金增量相差一个与行动无关的常数，保持期望行动排序；不能声称 MCCFR 每次随机样本或方差相同，也不能把不同窗口的数值直接相加成长期收益。

期初缴费及等待名单加入 checkpoint 的 `training_context`，防止续训串用；上下文策略家族允许读取同一核心库，具体节点仍须有平均策略覆盖。默认零缴费／空等待名单保持原规则、信息键与续训结果。公开查询、全范围首手采样使用同一完整资金基准，不需虚构对手底牌。

这是从明确经济状态开始的**新有限规划窗口**，不是恢复旧窗口未观察到的前手私牌历史。实际 WPK 的按钮、发牌名单、扣费前余额、逐席缴费归属及玩家连续性仍须先核实；当前采集协议不能提供全部依据，服务尚未自动应用此接口。默认核心训练起点仍为八人各 800 分、空旧池，接口支持非零池不等于这些节点已经训练或达到可用质量。

## 牌张码本与证据范围

作者补充材料第 12–14 页介绍了翻前 169 类、翻后 200 个 K-means 桶的结构。本项目采用自定义 27 维可见牌特征：已成牌型、踢脚、私牌等级、听顺／听花及公共牌纹理。**没有取得作者原码本或完整特征配置，也没有把这些特征称作 equity、对手范围或动作 EV。** 原文见 [Pluribus Supplementary Materials](https://noambrown.github.io/papers/19-Science-Superhuman_Supp.pdf)。

`mushroom_card_clusters.json` 由 `training/build_card_buckets.py` 固定种子 20261101 生成；每街 4096 个独立合成训练牌面、1024 个留出牌面，K-means++ 初始化、6 轮更新。每街 200 个桶均被使用。留出特征平方误差相对单一质心明显下降，仅证明特征压缩有效，不能证明扑克决策收益。JSON 内保存了具体数值和校验和，wheel 包含码本，不需联网下载或新增机器学习依赖。

在线搜索通过 `search_information_key` 保留实际私牌与完整公共信息，不会因为 blueprint 分桶而把当前玩家的两种实际持牌合并成一个搜索决策。公共根仍须由调用者提供一致的范围与到达概率；没有新增从 WPK 自动推断八人范围的功能。

## 检查点格式

自动核心训练现改用 `core/training.sqlite3`：旧 JSON 经严格校验后一次迁移，原文件保留；每轮事务提交全部增量与 RNG，全表折扣／快照流式执行。SQLite 不受下述旧 JSON 的 64 MiB 限制，导出使用 `texas-research checkpoint-backup` 单文件快照。以下格式与基准保留为 JSON 兼容及历史实验说明，不代表当前数据库文件限额。

新保存的 checkpoint 使用 JSON schema 2：公共动作列表只存一次，每条记录依次保存席位、信息键、动作列表索引、完整遗憾、完整策略累计量，以及 Pluribus 的下注轮。没有量化浮点数、删除节点或改变训练调度。原子写入、SHA-256、严格数据验证和 64 MiB 读取上限保留；schema 1 的旧检查点仍可加载，新文件需要更新后的后端。Blueprint 仍使用 schema 1。

测试对 CFR、MCCFR、Pluribus 比较旧／新格式加载后的每个数值和 RNG，并继续训练验证相同结果。减少序列化开销并不消除表格增长；地址空间和文件限额仍可能使长期自动训练进入 `limited`，此时保留最后完整检查点。

2026-11-01 的八人 800 分基准完成 200 轮，保存 278,622 个遗憾信息集与 272,690 个平均策略信息集。同一数据的旧格式 81,263,532 字节，新格式 50,069,929 字节，减少 38.4%；默认 64 MiB 限额内加载通过，两份数据续训第 201 轮后的累计值和 RNG 一致。信息集数量仍快速增长，不能把存储减少解读为已解决策略覆盖和无限持续训练。默认翻前积累周期为 10000；200 轮时第一下注轮还没有平均策略，因此尚不能提供该轮的训练策略建议。

新模型已用于本机自动 worker：加载 200 轮后继续保存到 201 轮。旧完整记忆模型的 147 轮工件完整归档，没有迁移或伪造为新模型的训练轮数。543 项 Python、11 项 Node、类型／schema／构建与 Ruff 通过；独立安装的 wheel 包含码本，进程重启后读取相同检查点。Chrome Origin 连接和心跳验证通过，未进行真实 WPK 行动推荐验收。原始数值、源码哈希及范围见[实验记录](experiments/mushroom-context.json)。

## 复现

在 WSL 项目目录执行：

```sh
uv run --frozen python training/verify_mushroom_context.py \
  --directory /home/ubuntu/Project/work/mushroom-context-new-run --iterations 200
```

目录必须是新的，避免覆盖已有检查点。实验使用八席各 800 分、2/4/8、两手视野、Pluribus 默认调度、固定种子 42；每轮有节点和时间预算，进程限制 1 GiB。实际完成数、检查点大小、信息集及加载结果由脚本记录，不能把请求轮数或节点数量当作强度指标。

上下文覆盖评测、稳定的实时搜索时延、真实牌谱训练、长期延续价值、re-straddle 和实局推荐仍需继续完成。当前候选不自动晋级为线上决策来源。
