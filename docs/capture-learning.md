# WPK 观察学习与玩家画像

这是 V1.0 的实采学习环节：公开行为进入可重放样本及持久行为统计，尚未构成实局建议或盈利评测。当前玩家身份只在 `Origin + source_id + player_id` 内有效，重新采集生成的新别名不能自动跨来源合并。

`NetworkStore.append` 在同一 SQLite 事务中保存原事件、牌局投影、学习样本和统计，再返回 ACK。重放不重复学习，冲突或失败整批回滚。学习 schema 版本 2 先检查派生数据版本；旧版即使水位已追平，也须在同一事务中从不可变事件重建，失败全部回滚，未来未知版本拒绝加载。原始记录不重置。

动作按手牌与 `source_event_id` 唯一识别。更新使用新的可见序号保存，历史 `as_of` 查询不会看到之后补充的字段。只有同手、明确且匹配的街道、没有已知乱序的动作才能保存可用的决策前观测；未知轮次、跨街补发等情况不附带可能属于未来的牌张。费用、盲注和 ante 不计作主动行为。

实采中筹码更新可能早于行动确认，因此不能使用“确认事件前一条”的余额作为行动前特征。版本 2 按来源保存一份当前决策锚点：行动请求后紧随的首个同手、同玩家、同公共牌快照，之后重复请求／快照不覆盖它。`observation_cutoff`／`history_reference` 指向这份快照，`decision_request_sequence` 保留请求来源。未及时取得快照、身份／街道冲突、缺口或关闭时，样本上下文 `available=false`；仍保留已观察动作及行为计数，不按动作金额倒推现金，也不补入后来出现的本人牌。

先前行动使用 `history_reference` 引用同一 Origin/source 内该手牌的不可变事件前缀及截止序号，需要完整序列时按截止点重建；样本不重复存储整手行动。当前按街道的行为统计不消费完整行动历史。采集 gap 即使携带旧手 ID，也会让实际受损的当前手失去完整结算标签资格。

画像统计当前已知街道的 FOLD/CHECK/CALL/BET/RAISE/ALL_IN 次数、实际频率及每类先验为 1 的 Dirichlet 分布，同时显示样本数与观测质量。它描述观察到的行为，**不是当前合法策略、手牌范围或动作 EV**。现有数据还不能核实已发牌玩家与行动机会分母，因此不展示 VPIP/PFR 或虚构的诈唬概率。

决策样本与最终结算分开。仅观察到开局、完整历史与行动、明确玩家名单且结算对账通过时，才附加 `reconciled_observation_only` 的整手结果标签。该标签仍未通过完整规则引擎核验；未选择动作的收益并不存在，不能把整手结果直接当 CFR 反事实奖励。

客户端协商 `capture_profiles_v1` 后，服务在 `capture.ack` 及已协商的状态消息之后推送 `capture.profiles`，schema 为 `tgto.capture-profiles/0.1`。只发送当前桌上的玩家；消息绑定来源和已确认序号，前端只展示当前最新状态的画像，断线或停止采集时清除。未协商的旧客户端不会收到新消息。

重连时若当前来源已经全部 ACK、没有新事件，客户端在普通队列处理完成后只重发一次最后一条原始业务事件，以既有幂等协议取回状态与画像；不会重计样本或不断循环补发。测试使用独立端口，不能让测试 ACK 服务占用实采端口 8765。

服务模块的 `profiles` 与 `examples` 提供有上限的读取；无论统计还是样本都携带来源和可见序号。当前没有将这些统计自动混入 Pluribus 基础策略。跨采集稳定身份、包含真实牌谱的评测集、数据归档与容量控制、条件范围建模及建议融合仍是 V1.0 发布前的工作。
