# WPK 业务解码：已实现的入口与仍缺失的字段依据

本版已实现页面已解码消息的**结构探针**。完整业务解码仍未完成：当前仓库及其全部 Git 历史只有入口与通知名称，没有原型字段映射、牌编码定义、真实消息样本或金额语义证据。探针用于取得这些结构依据，不能称为已还原牌局。

## 直接使用

1. `npm ci`、`npm run build`，在 Chrome 扩展管理页加载或重新加载 `dist/`。
2. 在自己的 Chrome 正常打开 WPK，选择该标签页，点击“开始采集”。本地观察不需要连接 Python 服务。
3. 侧栏“WPK 业务接入”显示探针最近状态。`observing` 表示找到了分发入口，**不代表手牌／行动已经解码**。
4. 正常观察牌桌消息，最多 2 分钟。点击“导出 WPK 结构报告”，检查动态字段名后分享给开发者。报告不进入服务器 outbox。
5. 若已有文档提到的旧原型，直接提供包含 `HMFClient`／`WPGameData` 映射的源码路径或仓库；它比单纯字段结构更能确定语义。

`entry_missing` 表示指定入口在观察期内未找到；`entry_unsupported` 表示入口形态不可用；`sample_limit` 表示有界采样已停止；`entry_replaced` 表示页面替换了已包装方法。停止再开始可以建立新的采样 epoch。未确认的入口不会退回到猜测二进制协议。

## 已有实现

- `extension/wpk/page-probe.js`：在允许页面的默认执行上下文探测全局 `HMFClient`，或 Cocos `__require('HMFClient')`；尝试 `sharedInstance()._dispatchMessageToCC`。这些路径来自仓库线索，尚未在当前真实 WPK 版本验证。
- 观察分发参数的字段结构，识别已知通知字符串：`WP_actionNotify`、`WP_actionHistoryNotify`、`WP_userOptNotify`、`WP_roundChangeNotify`、`C_playLogNotify`、`C_updateRoomDetail`、`C_closeRoomNotify`。通知名称用于结构分组，不推断其字段含义；`userAciton` 保留原拼写。
- 包装方法恰好调用原方法一次，保留 `this`、参数、返回对象／Promise 身份和原异常。结构检查在分发后的 microtask 执行，不把此时点当成异步手牌解码完成时点。
- 不调用下注方法，不拷贝解密密钥，不展开 `WPGameData` 玩家数据。牌、凭据和身份字段不向下展开；普通字段也只记录类型，不导出值。getter 不执行，Proxy 或结构异常被隔离。
- 只处理最多 4 个参数、每个对象前 24 个自有字段、深度 4 层和最多 64 个结构节点；数组仅检查一个代表项的类型结构。重复结构去重，不能据此计算实际行动次数。
- 每上下文最多 8 个待处理观察、256 次检查、64 种结构、128 个报告，最长 120 秒；触及采样限制会显式结束观察。新通知类别或遗漏时段不会被宣称已覆盖。
- 用户停止时对仍可访问的上下文恢复原属性描述符并移除绑定。若页面已经换了方法，不覆盖它；扩展意外消失时，有限租约最终恢复当前探针仍拥有的方法。
- `probe-bridge.ts`：验证 CDP target、默认 context、页面 Origin、随机 binding 名与严格报告 schema；拒绝跨 context／跨源／超限或夹带字段值的报告。仅 `auxData.isDefault === true` 的允许上下文会安装探针，不能声称所有 Worker 世界已覆盖。
- `probe-store.ts`：独立本地 IndexedDB，严格事务分配报告索引。每源最多 256 条／2 MiB，最多 32 个源；达到限制显示错误，不自动删除已有报告。网络归档和发送队列保持独立。

报告的 `adapter_verified: false` 始终保留。字段名也可能由业务数据动态生成，分享前仍需人工检查；路径规则会掩去数字、UUID 和非标识符键，但不能把任意动态名字保证为匿名信息。

## 还缺什么才能输出真实业务事件

必须核实分发参数签名／消息信封，以及下面的实际映射：

| 目标字段 | 缺失的证据 |
| --- | --- |
| 桌、手、座位与源动作 ID | 字段路径、重连语义、作用域和连续性 |
| 本人底牌、公共牌 | 本人身份判定、可见性、牌编码、异步就绪时点 |
| fold/check/call/bet/raise/all-in | 枚举含义、请求与确认的区别 |
| 筹码／跟注／加注金额 | 分或其他单位、增量还是累计、本街还是整手 |
| 盲注、straddle、蘑菇费与奖池 | 发牌前事件顺序与所属手、余额变化含义 |
| 主池／边池／结算 | 独赢与平分的表示、未跟注返还和终局余数 |

结构报告能定位字段，但不证明金额含义或牌编码。取得旧原型或带语义标注的脱敏实例后，才能编写并验证实际字段转换、独立业务流 `capture_events_v1` 和权威状态归约。当前服务器仍只确认网络元数据，不接受这些诊断报告，也不生成真实行动推荐。

## 验证边界

新增 8 项测试验证原调用完整性、异常、Promise、getter 隔离、隐私字段不展开、Cocos 入口、方法恢复、租约、编译后的序列化注入、严格 schema、context/Origin 隔离、独立持久化和限额回滚。本轮 28 项 Node 测试、TypeScript 检查、实际 WASM／扩展构建和 1 项真实 Python 跨仓库联调均通过。

浏览器合成场景已加入假 HMFClient 的调用／报告断言；它验证的是探针机制，样本不是 WPK 实际协议。当前云环境的管理员策略禁止加载未打包扩展，不能完成真实 Chromium 或 WPK 验收；本地单元测试不能替代该验证。

本轮回归另修复了已有 WebSocket 的关闭竞态：连接关闭后排队的状态／错误帧可能使重传意外停止。关闭连接会作废旧 generation，且消息处理检查 socket 状态；跨仓库测试强制注入关闭后的残留帧验证重传继续完成。
